API TempMail RouterSSH

Inbox sementara untuk workflow otomatis.

Buat alamat, tunggu email masuk, ambil OTP atau tautan verifikasi, lalu hapus inbox ketika selesai. Semua endpoint menggunakan JSON dan tersedia melalui HTTPS.

Base URL https://tempmail.routerssh.web.id/api

  4. 4Hapus inbox setelah workflow selesai.

01

Dasar

Authentication

Endpoint yang mengakses inbox memakai API key milik alias. Kirim key melalui header X-API-Key.

Simpan key saat alias dibuat.

Nilainya hanya dikembalikan oleh POST /api/alias. Jika hilang, inbox tidak dapat dibuka kembali melalui API.

HTTP header
X-API-Key: temp-REPLACE_WITH_YOUR_KEY
02

5 langkah

Mulai cepat dengan curl

Contoh ini menggunakan placeholder. Jangan masukkan key produksi ke source code atau repository.

1. Buat inbox

Shell
curl -sS -X POST 'https://tempmail.routerssh.web.id/api/alias' \
  -H 'Content-Type: application/json' \
  -d '{"duration":"1h"}'

Response 200 OK

{
  "id": "ALIAS_ID",
  "email": "random@routerssh.web.id",
  "expires_at": "2030-01-01T01:00:00Z",
  "api_key": "temp-REPLACE_WITH_YOUR_KEY"
}

2. Tunggu email baru

Shell · long polling
curl -sS 'https://tempmail.routerssh.web.id/api/wait?after=0&timeout=30' \
  -H 'X-API-Key: temp-REPLACE_WITH_YOUR_KEY'

Server menunggu hingga 30 detik. Jika belum ada pesan, response adalah 408; panggil lagi dengan retry yang dibatasi. Setelah menerima pesan, simpan id sebagai nilai after berikutnya.

3. Ambil isi pesan

Shell
curl -sS 'https://tempmail.routerssh.web.id/api/email/EMAIL_ID' \
  -H 'X-API-Key: temp-REPLACE_WITH_YOUR_KEY'

4. Ekstrak OTP atau link

Shell
curl -sS 'https://tempmail.routerssh.web.id/api/extract/EMAIL_ID' \
  -H 'X-API-Key: temp-REPLACE_WITH_YOUR_KEY'

5. Hapus inbox

Shell
curl -sS -X DELETE 'https://tempmail.routerssh.web.id/api/alias' \
  -H 'X-API-Key: temp-REPLACE_WITH_YOUR_KEY'

Implementasi

Lifecycle lengkap

JavaScript · Node.js 18+
const baseUrl = 'https://tempmail.routerssh.web.id/api';

const aliasResponse = await fetch(`${baseUrl}/alias`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ duration: '1h' })
});
if (!aliasResponse.ok) throw new Error(`Create failed: ${aliasResponse.status}`);

const alias = await aliasResponse.json();
const headers = { 'X-API-Key': alias.api_key };
let lastEmailId = 0;

try {
  while (true) {
    const response = await fetch(
      `${baseUrl}/wait?after=${lastEmailId}&timeout=30`,
      { headers }
    );
    if (response.status === 408) continue;
    if (!response.ok) throw new Error(`Wait failed: ${response.status}`);

    const email = await response.json();
    lastEmailId = email.id;

    const extractedResponse = await fetch(
      `${baseUrl}/extract/${email.id}`,
      { headers }
    );
    if (!extractedResponse.ok) {
      throw new Error(`Extract failed: ${extractedResponse.status}`);
    }

    const extracted = await extractedResponse.json();
    console.log({ address: alias.email, ...extracted });
    break;
  }
} finally {
  await fetch(`${baseUrl}/alias`, { method: 'DELETE', headers });
}
Python 3 · standard library
import json
import urllib.error
import urllib.request

BASE_URL = "https://tempmail.routerssh.web.id/api"


def request(path, *, method="GET", api_key=None, body=None):
    headers = {"Accept": "application/json"}
    data = None
    if api_key:
        headers["X-API-Key"] = api_key
    if body is not None:
        headers["Content-Type"] = "application/json"
        data = json.dumps(body).encode()
    req = urllib.request.Request(
        BASE_URL + path, data=data, headers=headers, method=method
    )
    try:
        with urllib.request.urlopen(req, timeout=135) as response:
            return response.status, json.load(response)
    except urllib.error.HTTPError as error:
        payload = json.loads(error.read().decode())
        return error.code, payload


status, alias = request("/alias", method="POST", body={"duration": "1h"})
if status != 200:
    raise RuntimeError(alias)

api_key = alias["api_key"]
last_email_id = 0

try:
    while True:
        status, email = request(
            f"/wait?after={last_email_id}&timeout=30", api_key=api_key
        )
        if status == 408:
            continue
        if status != 200:
            raise RuntimeError(email)

        last_email_id = email["id"]
        status, extracted = request(
            f"/extract/{last_email_id}", api_key=api_key
        )
        if status != 200:
            raise RuntimeError(extracted)
        print({"address": alias["email"], **extracted})
        break
finally:
    request("/alias", method="DELETE", api_key=api_key)
04

Referensi

Endpoint

POST/aliasBuat inbox

Tidak memerlukan authentication. Body kosong membuat alias 24 jam. Untuk request JSON, gunakan:

  • duration: 1h, 24h, 7d, 30d, atau forever.
  • email: opsional, nama lokal atau alamat lengkap pada domain routerssh.web.id.

Response mengembalikan id, email, expires_at, dan api_key. Alias duplikat menghasilkan 409.

GET/aliasesDetail alias

Memerlukan API key. Mengembalikan alias yang dimiliki key tersebut dalam object {"aliases": [...]}.

GET/messagesDaftar pesan

Endpoint automation yang direkomendasikan. Memerlukan API key dan tidak memerlukan alamat pada URL.

  • after: ID minimum, default 0.
  • full=1: sertakan body_text dan body_html.

Tanpa full, response hanya memuat metadata pesan.

GET/email/:idIsi satu pesan

Memerlukan API key yang memiliki pesan tersebut. Mengembalikan sender, recipient, subject, body text, body HTML, waktu masuk, dan status baca.

GET/waitTunggu pesan baru

Long polling berdasarkan alias milik API key.

  • after: ID pesan terakhir, default 0.
  • timeout: 1–120 detik, default 30.

Mengembalikan pesan paling lama yang belum diproses agar burst email tidak terlewat. Timeout normal menggunakan HTTP 408.

GET/extract/:idEkstrak data

Mencari kode verifikasi 4–8 digit, link verifikasi, dan token pada email. Field code, link, atau token hanya muncul jika ditemukan.

POST/sendKirim email

Memerlukan API key yang memiliki alamat from. Email dikirim sebagai plain text.

{"from":"alias@routerssh.web.id","name":"Nama opsional","to":"tujuan@example.com","subject":"Subjek opsional","body":"Pesan wajib"}
DELETE/aliasHapus inbox

Memerlukan API key. Menghapus alias milik key beserta seluruh pesannya. Response: {"success": true}.

DELETE/emails/:addressKosongkan inbox

Memerlukan API key pemilik alamat. Alias tetap aktif, hanya semua pesan di dalamnya yang dihapus. Response menyertakan jumlah deleted.

GET/healthStatus layanan

Tidak memerlukan authentication. Response sehat: {"status":"ok","server":"tempmail-cpp"}.

Endpoint kompatibilitas browser

GET /emails/:address, GET /check/:address, GET /wait/:address, dan DELETE /alias/:address tetap tersedia. Untuk worker baru, gunakan /messages, /wait, dan DELETE /alias agar alamat tidak perlu dikirim di URL.

05

Reliability

Error handling

400Payload atau parameter tidak valid
401API key tidak ada atau tidak valid
403Key bukan pemilik alamat pengirim
404Alias atau pesan tidak ditemukan
408Long polling selesai tanpa pesan baru
409Alias khusus sudah digunakan
500Gangguan penyimpanan atau pengiriman

Retry 408 secara normal. Untuk 500 atau gangguan jaringan, gunakan bounded exponential backoff. Jangan retry 400, 401, 403, atau 409 tanpa memperbaiki request.

06

Operasional

Penyimpanan API key

01

Gunakan header

Kirim key melalui X-API-Key, bukan query URL, agar tidak masuk ke history dan access log.

02

Jangan commit

Simpan key di environment variable atau secret manager. Jangan masukkan ke source, screenshot, atau log.

03

Satu key, satu alias

Setiap key hanya dapat membaca dan menghapus alias yang dimilikinya.

04

Hapus setelah selesai

Panggil DELETE /alias di blok cleanup atau finally.
